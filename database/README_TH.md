# ตั้งค่า Supabase สำหรับกลุ่มทดลอง

รุ่นล่าสุด: หลังติดตั้ง 001 ให้รัน `migrations/002_ml_gi_pilot.sql` และ `migrations/003_traceability.sql` ตามลำดับ เพื่อเปิด ML/GI และประวัติเลี้ยง/หลักฐานตามล็อต ดู [คู่มือ Traceability](../TRACEABILITY_TH.md)

1. สร้าง Supabase โปรเจกต์สำหรับทดสอบ แล้วรัน `migrations/001_spark_pilot.sql` ใน **SQL Editor** ด้วยบัญชีผู้ดูแล Migration เพิ่ม schema ใหม่และเก็บตารางเก่าไว้ ข้อมูลเดโมในเบราว์เซอร์ยังเปิดได้ด้วยค่าเริ่มต้นใน ZIP
2. ใน **Authentication → Users** สร้างบัญชีอีเมลและรหัสผ่านแยกกันอย่างน้อยผู้ประสานหนึ่งบัญชี ผู้เลี้ยงหนึ่งบัญชี และผู้ซื้อสองบัญชี ใช้อีเมลจริงที่ทีมควบคุมและยืนยันบัญชีทดสอบใน Dashboard เลือกอีเมลที่ต่างกันทั้งห้าบัญชีหากจะตรวจการแยกผู้เลี้ยงด้วย
3. แก้อีเมลและชื่อใน `add-members.example.sql` แล้วรันใน SQL Editor บัญชีที่ไม่มีใน Auth จะทำให้สคริปต์หยุดก่อนบันทึกสมาชิก หากใช้สี่บัญชีให้เอาบรรทัดผู้เลี้ยง B ออกจากรายการตัวอย่าง ชื่อกลุ่มตั้งต้นคือ `sala-hum-pilot`
4. คัดลอก `assets/js/database-config.example.js` ไปแทน `assets/js/database-config.js` แล้วใส่ **Project URL** และ **Publishable key** จาก Supabase > Connect ให้ `workspace` ตรงกับรหัสกลุ่มใน SQL ค่านี้ใช้บนหน้าเว็บได้ เก็บรหัสผ่านและ Secret key ไว้นอกไฟล์เว็บและ GitHub เมื่อแก้การเชื่อมต่อ ให้เปลี่ยนค่า `v` ในลิงก์ `database-config.js?v=...` ทุกหน้าและลิงก์เข้ากลุ่มใน `index.html` เพื่อให้เบราว์เซอร์โหลดค่าล่าสุด
5. หากต้องการใช้ “ลืมรหัสผ่าน” เพิ่ม URL เต็มของ `reset-password.html` ใน **Authentication → URL Configuration → Redirect URLs** และตั้งค่าอีเมลของโปรเจกต์ให้ส่งถึงผู้ใช้ได้

## บัญชีและสิทธิ์สำหรับทดสอบ

| บัญชีตัวอย่าง | สิ่งที่ควรเห็นหลังล็อกอิน |
| --- | --- |
| `coordinator@example.invalid` | กระชังและออเดอร์ในกลุ่ม จัดสรรปลา เปิดขาย ตรวจแผน จัดรอบส่ง และบันทึกการเงิน |
| `farmer-a@example.invalid` | กระชังและค่าน้ำของ A งานดูแล แผน ออเดอร์ที่เชื่อมกับกระชัง และเงินรับของ A |
| `farmer-b@example.invalid` | กระชังของ B และยอดของ B ใช้ตรวจว่าไม่เห็นรายการส่วนตัวของ A |
| `buyer-a@example.invalid` | รายการเปิดขาย คำขอและรอบส่งของร้าน A |
| `buyer-b@example.invalid` | รายการเปิดขาย คำขอและรอบส่งของร้าน B ใช้ตรวจว่ามองไม่เห็นออเดอร์ของ A |

โหมดกลุ่มเริ่มจากกระชังและออเดอร์ว่าง ผู้เลี้ยงเพิ่มกระชังจากหน้ากระชังได้ ผู้ประสานเปิดรายละเอียดกระชังแล้วตั้งปริมาณเปิดขายและราคา รายการจะขึ้นในหน้าสั่งปลาหลังผู้ซื้อกดโหลดล่าสุด ราคากลุ่มมีผลกับคำขอใหม่ ออเดอร์เดิมใช้ราคาที่บันทึกไว้แล้ว

## ตรวจบนสองเครื่อง

1. เครื่องแรกเข้าด้วยผู้เลี้ยง A เพิ่มกระชังปลาเก๋า 250 ตัว เฉลี่ย 0.8 กก. และบันทึกอาการโดยเว้นค่าน้ำที่ยังไม่มี เครื่องที่สองใช้ผู้ประสานแล้วกด “โหลดข้อมูลล่าสุด” เพื่อตรวจว่ากระชังและงานดูแลปรากฏ
2. ผู้ประสานเปิดขาย 50 กก. ที่ 340 บาท/กก. บนเครื่องที่สอง สลับบัญชีบนเครื่องแรกเป็นร้าน A ส่งคำขอ 20 กก. แล้วออกจากระบบ ล็อกอินร้าน B ส่งคำขอ 30 กก. และตรวจว่าหน้าออเดอร์ของ B ไม่มีของ A
3. ให้ผู้ประสานจัดสรรทั้งสองคำขอ ผู้เลี้ยงและแต่ละร้านยืนยัน จากนั้นร่างแผน 50 กก. ยืนยันคุณภาพและรถ อนุมัติ ชั่งจริง แล้วสร้างและส่งรอบของแต่ละร้าน
4. ให้ร้าน A และ B รับจริง 20 และ 30 กก. จากบัญชีของตน ผู้เลี้ยงกด “โหลดข้อมูลล่าสุด” แล้วดูเงินรับสุทธิ ควรเห็นรับจริง 50 กก. ขาย 17,000 บาท และสุทธิก่อนต้นทุนเลี้ยง 16,000 บาท เมื่อค่าแพ็ก รถ และบริหารกลุ่มรวม 1,000 บาท
5. เพิ่มกระชัง B หรือใช้บัญชีอีกกลุ่ม ตรวจว่าข้อมูลของ A เปิดผ่านบัญชีที่ไม่เกี่ยวข้องไม่ได้ ทดสอบปิดเน็ตตอนกดบันทึกแล้วเปิดใหม่ ตรวจร่างและจำนวนรายการหลังลองซ้ำ

ฐานข้อมูลเก็บประวัติเป็นชุดข้อมูลต่อกลุ่มสำหรับการทดลองขนาดเล็ก ตารางเปิด RLS และสงวนการเข้าถึงโดยตรง ฟังก์ชันอ่านและบันทึกตรวจสมาชิกและบทบาทจาก `auth.uid()` ทุกครั้ง ฟังก์ชันบันทึกล็อกข้อมูลกลุ่ม ตรวจรุ่นล่าสุด และจดรหัสคำขอในธุรกรรมเดียวกัน บัญชีเข้าถึงเฉพาะผลที่ผ่านการกรองแล้ว
