# ปลาศาลาหุม

รุ่นเพิ่ม Machine Learning และงาน GI/Thai SELECT: อ่าน [คู่มือรุ่นใหม่](PILOT_UPDATE_TH.md) ก่อนทดลอง ส่วนฟีเจอร์ใหม่ในโหมดข้อมูลร่วมต้องติดตั้ง migration `002_ml_gi_pilot.sql` หลัง `001`


ต้นแบบ SPARK HACK PTT สำหรับบ้านศาลาหุม อ.สิงหนคร จ.สงขลา ใช้ HTML แยก 24 หน้า พร้อม CSS และ Vanilla JavaScript จากต้นแบบ GitHub สาขา `main` ที่ commit `a8f5409` ชุดนี้ทำงานได้โดยไม่ต้องติดตั้งแพ็กเกจสำหรับหน้าเว็บ

## เปิดจาก ZIP

1. แตก `Spark_Hack_Prototype.zip` แล้วเปิด Terminal ในโฟลเดอร์ `Spark_Hack_Prototype` ที่มี `index.html`
2. รันคำสั่งด้านล่าง โดยใช้ `py` แทน `python3` บน Windows หากติดตั้ง Python Launcher
3. เปิด [localhost:8000](http://localhost:8000/) อ่านหน้าแจ้งการใช้ข้อมูลส่วนบุคคล แล้วกด **รับทราบและไปต่อ** จากนั้นเลือก **ลองเดโม** หรือ **เข้ากลุ่มของฉัน**

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

ใช้ HTTP Server เพื่อให้ข้อมูลเบราว์เซอร์ทำงานข้ามหน้า การเปิด HTML โดยดับเบิลคลิกขึ้นอยู่กับการรองรับพื้นที่เก็บข้อมูลแบบ `file://` ของแต่ละเบราว์เซอร์

## เปิดบนมือถือ

เมื่อมีเว็บที่เผยแพร่แล้ว เปิด URL บนมือถือหรือสแกน QR ที่ทีมแชร์ ใน Wi‑Fi เดียวกับคอมพิวเตอร์ให้เปิดเซิร์ฟเวอร์ด้วยคำสั่งด้านล่าง แล้วใช้ IPv4 ของคอมพิวเตอร์ใน URL เช่น `http://192.168.1.20:8000/` หา IPv4 จาก `ipconfig` บน Windows หรือรายละเอียด Wi‑Fi บน macOS ใช้ `Ctrl+C` เพื่อหยุดเซิร์ฟเวอร์

```bash
python3 -m http.server 8000 --bind 0.0.0.0
```

## ลองเดโม

กดปุ่มขั้นถัดไปด้านบนเพื่อไปหน้าที่ต้องใช้และสลับเป็นบัญชีตัวอย่างในขั้นนั้น หรือใช้ **สลับบทบาท** เพื่อเลือกเอง บันทึกได้แม้มีเพียงอาการหรือสิ่งที่สังเกต ข้อมูลเดโมเก็บในเบราว์เซอร์และคงอยู่หลังรีเฟรช หน้า **วิธีใช้ / สาธิต** มีปุ่ม **เริ่มเดโมใหม่** ซึ่งรีเซ็ตเฉพาะชุดทดลองของเว็บนี้

เส้นทางปกติใช้ปลาเก๋า 20 + 30 กก. ที่ 340 บาท/กก. รับจริงรวม **50 กก.** ยอดขาย **17,000 บาท** หักแพ็ก 250 บาท รถ 500 บาท และบริหารกลุ่ม 250 บาท เหลือ **16,000 บาทก่อนต้นทุนเลี้ยง** ดูอีกสองสถานการณ์และรายละเอียดใน [DEMO_GUIDE_TH.md](DEMO_GUIDE_TH.md)

## หน้าแจ้งการใช้ข้อมูล

เว็บแสดงประกาศครั้งแรกในแต่ละแท็บก่อนเปิดเดโม โหมดกลุ่ม และลิงก์หน้าทำรายการโดยตรง กด **การใช้ข้อมูลส่วนบุคคล** ท้ายหน้าเพื่ออ่านซ้ำ การรับทราบเก็บเฉพาะรุ่นข้อความในแท็บ ไม่มีการส่งสถานะไปฐานข้อมูล หากแก้ข้อความที่มีสาระสำคัญ ให้แก้ค่า `version` ใน `assets/js/privacy.js` เพื่อให้เห็นประกาศฉบับใหม่

หากทีมจะบันทึกภาพ เสียง หรือหน้าจอในการประเมินการใช้งาน ให้ขออนุญาตแยกตามกิจกรรมนั้น ผู้จัดโครงการต้องยืนยันชื่อผู้ควบคุมข้อมูล ผู้รับข้อมูล ระยะเก็บ ช่องทางใช้สิทธิ และฐานกฎหมายก่อนใช้ข้อมูลจริงในโหมดกลุ่ม

## เชื่อมโหมดกลุ่ม

รัน migration สร้างบัญชีใน Supabase Auth และใส่ URL กับ Publishable key ใน `assets/js/database-config.js` ตาม [คู่มือตั้งค่า Supabase](database/README_TH.md) จากนั้นกด **เข้ากลุ่มของฉัน** บทบาทมาจากบัญชีที่ผู้ดูแลกำหนด ใช้ **โหลดข้อมูลล่าสุด** เพื่อดูรายการที่คนอื่นบันทึก ร่างฟอร์มอยู่ในแท็บเดิมเมื่อบันทึกพลาด หากมีการเปลี่ยนข้อมูลกลาง ให้โหลดล่าสุดแล้วตรวจค่าที่กรอกก่อนกดอีกครั้ง

ยอดเงินเกิดเมื่อผู้ซื้อยืนยันน้ำหนักรับจริง ส่วนการเก็บและจ่ายเงินเป็นการบันทึกสถานะในเว็บ กฎค่าน้ำช่วยชี้สิ่งที่ควรตรวจต่อ การยืนยันคุณภาพใช้ผลตรวจของผู้รับผิดชอบ

## อัปโหลดขึ้น GitHub repo ใหม่

1. สร้าง repository ใหม่ แล้วอัปโหลด **ไฟล์และโฟลเดอร์ข้างใน** `Spark_Hack_Prototype` ให้ `index.html` และ `.nojekyll` อยู่ที่รากเดียวกับ `assets/` บนสาขา `main` ตรวจว่าอัปโหลด `.nojekyll` ครบ หากเลือกผ่าน File Explorer ให้เปิดแสดงไฟล์ซ่อนก่อน
2. ใน **Settings → Pages** เลือก **Deploy from a branch → main → /(root)** แล้วบันทึก รอ GitHub แสดงลิงก์ที่เผยแพร่แล้ว
3. เปิดลิงก์ในหน้าต่างไม่ระบุตัวตน กด **ลองเดโม** และลองบนมือถือก่อนนำลิงก์ไปทำ QR

หากใช้ Git ในโฟลเดอร์ที่แตก ZIP ให้เปลี่ยน `YOUR_GITHUB_REPO_URL` เป็น HTTPS URL ของ repository ใหม่ แล้วรัน

```bash
git init -b main
git add .
git commit -m "Add Spark Hack prototype"
git remote add origin YOUR_GITHUB_REPO_URL
git push -u origin main
```

[คู่มือ GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## แก้ไฟล์และรันทดสอบ

- แก้โครงหน้าใน HTML แยกไฟล์ และแก้การทำงานของหน้าที่ชื่อเดียวกันใน `assets/js/pages/`
- เดโมเก็บข้อมูลตัวอย่างใน `assets/js/demo-data.js` ใช้กฎใน `risk-engine.js`, `calculations.js` และ `domain.js`
- โหมดกลุ่มเรียก Supabase ใน `assets/js/cloud.js` กฎธุรกรรมและการตรวจสิทธิ์อยู่ใน `database/migrations/`
- ตรวจไฟล์ด้วย `python3 tests/check-files.py` และทดสอบกฎด้วย `node tests/run-node.js`
- เปิด `tests/zip-check.html` ในหน้าต่างไม่ระบุตัวตนเพื่อทดสอบเดโมครบขั้นจากไฟล์ที่แตก ZIP
- ทดสอบ SQL ใน PostgreSQL จำลองการยืนยันตัวตนด้วย `npm install --no-save @electric-sql/pglite` แล้ว `node tests/group-postgres.mjs` ใช้สำหรับทดสอบเท่านั้น
